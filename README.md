# 深渊回响 · Echoes of the Abyss

一个纯前端的 2.5D 俯视割草肉鸽（rogue-lite）。零依赖、零构建、零外部资源 —— 双击 `index.html` 就能玩。

> 无限波次 · 词条随机装备 · 行囊与羁绊 · 30 种升级特性 · 可刷新黑市 · 6 名差异化角色 · 没有 BOSS，只有无穷无尽的怪潮。

---

## 快速开始

```bash
# 方式一：直接双击
index.html

# 方式二：起个本地服务（推荐）
python -m http.server 8080
# 打开 http://localhost:8080
```

**操作**

| 按键 | 作用 |
| --- | --- |
| `W A S D` / 方向键 | 移动 |
| 鼠标 | 瞄准（离角色远时手动瞄准，贴近时自动锁定最近的敌人） |
| `空格` | 冲刺（带无敌帧；点了「冲刺大师」后带伤害） |
| `Tab` / `B` | 打开行囊（游戏暂停，可换装、丢弃） |
| `Esc` | 暂停 |
| `M` | 静音 |

攻击是**全自动**的，玩家只管走位 + 管装备。

**调试 / 演示参数**（挂在 URL 上）

```
?autostart=rayn                直接以雷恩开局
?autostart=nyx&sim=40          开局后快进模拟 40 秒
&hold=levelup / &hold=shop     快进到升级 / 商店就停下
&bag=1                         开局直接打开行囊
&die=1                         立即死亡，看结算界面
```

## 玩法循环

```
杀怪 → 掉经验/金币/装备 → 装备进行囊，挑选佩戴
   → 升级三选一 → 42 秒一波结束 → 黑市（可刷新）→ 下一波更强
```

死亡即结束，没有复活。

## 装备与行囊（核心系统）

### 佩戴位 vs 行囊

| 位置 | 容量 | 规则 |
| --- | --- | --- |
| **佩戴位** | 武器 ×1、防具 ×1 | **只有放在这里才生效** |
| **行囊** | 12 格起，可扩容至 24 | 饰品放进来**即生效**；武器/防具放进来不生效，只作备用 |

这套规则让"行囊空间"成为真正的资源：

- **饰品流**：12 格全塞饰品 → 属性最大化、羁绊容易堆高，但换不了新武器防具
- **均衡流**：留 2-3 格放备用武器防具 → 随时换装，但饰品少一半
- **行囊满时无法拾取**，地上的装备会亮出「行囊已满」，需要回城（Tab）丢弃或替换

**行囊怎么变大**

| 来源 | 增量 |
| --- | --- |
| 基础 | 12 格 |
| 角色等级 | 每 5 级 +1（5 / 10 / 15 …） |
| 「扩容行囊」特性 | 每层 +2，最多 3 层 |
| 装备「行囊」词条 | 每件 +1 |
| **上限** | **24 格** |

扩容是构筑的一部分：前期 12 格逼你取舍，中后期堆到 18~24 格才能真正跑起「全饰品 + 高层羁绊」，
而「扩容行囊」本身要占掉一次升级选择。容量因换装而缩小时，越界物品会自动收回或折算成金币，不会凭空消失。

行囊里可以：
- 点击武器/防具 → 与佩戴位互换
- 点右上角 `⊗` → 丢弃，回收 25% 价格的金币
- 悬停 → 看完整属性，并与当前佩戴的同类装备比较强弱（▲/▼）

### 数值随机（三层叠乘）

同一把「断钢长剑」每局、每一波掉落的数值都不一样：

```
最终属性 = 基础值 × 等级强度 × 随机浮动(0.90~1.06) × 稀有度倍率
```

- **等级强度** `1 + (波次-1) × 0.19` —— 老装备会自然淘汰
- **稀有度**：普通 / 稀有 / 史诗 / 传说 / 神话，倍率 1.0 → 1.85
- **词条**：16 种词条池，按稀有度随机 0~4 条，数值再 ±20% 浮动
- **命名**：稀有度前缀 + 基础名，例如「深渊的龟甲符」

## 视觉语言：羊皮纸 UI + 像素世界

### 界面层：羊皮纸 / 墨迹 / 火漆印

不使用玻璃拟态、不使用霓虹发光：

- 纸张由 SVG `feTurbulence` 实时生成的纤维噪点 + 多块色斑渐变 + 做旧污渍叠成，全部内联，无外部图片
- 层次靠**实心投影**（2-3px 硬阴影）与双线内框建立，而不是模糊光晕
- 稀有度用**印泥色**：褐（普通）/ 靛蓝（稀有）/ 紫（史诗）/ 赭金（传说）/ 朱红（神话）
- 强调色只有一味朱红（火漆），用于等级徽章、选中印、关键数值

### 世界层：像素贴图

角色、怪物、装备图标、地面全部是**手绘像素点阵**，不是 AI 生成图，也不是外部 PNG：

```
16×16 的字符矩阵 + 调色板  →  烘焙成 canvas 纹理  →  drawImage
```

- **零资源**：所有贴图都是代码里的字符串，改一行就改一个像素，颜色改调色板即可整体换肤
- **风格统一**：42 张精灵（10 怪 + 6 角色 + 26 装备）用同一套 4–5 色调色板规范绘制
- **可换色**：稀有度、职业配色只需替换 `pal`，不必重画
- **受击闪白**用预烘焙的纯白剪影叠加，零运行时开销
- **地面**是程序化生成的：4 层噪声（微颗粒 / 中块 / 大色块 / 苔藓斑）合成 4 块 256×256 地块，
  平铺时按坐标哈希挑块；其上再稀疏撒一层手绘装饰（石砾 / 枯骨 / 枯草 / 发光菌 / 裂纹 / 头骨）
- 渲染时全局关闭 `imageSmoothingEnabled`，保证像素锐利

**为什么不用图片文件**：42 张图会带来加载、打包、风格漂移、透明通道等一系列问题；
点阵数据可读、可 diff、可参数化，且和「双击 index.html 就能玩」的约束天然契合。

### 一致性

游戏世界底色是暖褐（古地图感），与羊皮纸 UI 同一色温；敌人用高饱和的红/橙/绿/紫保证辨识度，
像画在旧地图上的朱砂标记。

想看全部贴图：打开 `test/gallery.html`。

## 架构设计

### 分层

```
js/core     种子随机 / 数学 / 空间哈希 / 合成音效     —— 无业务
js/data     词条·装备·羁绊·特性·角色·敌人             —— 纯静态配置
js/sim      loot / combat / world / net               —— 纯模拟，可跑在 Node
js/render   icons / renderer                          —— 只读 world
js/ui       ui                                        —— DOM 层，只读 world + 发指令
```

**核心约束**：`sim` 层不碰 DOM、不读鼠标、不碰 Canvas，所有随机走 `world.rng`。

### 为联机预留

这个项目从第一行代码就为「服务器 + 多人」留了接口，虽然本期不实现：

1. **确定性模拟** —— 同种子 + 同输入序列 → 完全一致的世界状态（`test/sim-test.js` 有验证用例）
2. **状态与表现分离** —— `World.snapshot()` 输出可序列化快照，渲染层每帧只读
3. **输入离散化** —— 方向量化成 `-1/0/1`，瞄准角量化到 1/256 圈
4. **协议已定义** —— `HELLO / WELCOME / INPUT / SNAPSHOT / EVENT / PING / PONG`

推荐的联机模型是**服务器权威 + 客户端预测**（割草场景实体太多，帧同步和回滚成本都不可接受）：

```
客户端                          服务端
采集输入 ──────────────────►  权威 World.step(1/60)
本地预测移动                    每 50ms 广播快照
◄──────── 快照 ────────────   掉落 / 词条 / 商店全部服务端 roll
误差 >140px 瞬移；>8px 插值
```

`ServerRoom`（`js/sim/net.js`）已经是可运行的骨架。真要开多人，剩下的是：把 `World.player` 扩展成 `players[]`、敌人仇恨改为最近玩家、掉落归属规则、房间与重连。

### 性能

- 空间哈希宽相碰撞（96px 格子），避免 O(n²)
- 复用查询缓冲数组，零帧分配
- 地面用预渲染 tile 平铺；实体走纯色 + 高光而非渐变
- 同屏敌人硬上限 220、粒子 700、伤害飘字 140
- 实测：220 怪物 + 200 投射物时，单帧模拟 ≈ 0.2~1ms

## 测试

```bash
node test/sim-test.js          # 逻辑回归（无需浏览器）
node test/ui-state-test.js     # 界面状态机回归（弹层走位）
node test/browser-check.js combat 7   # 真实浏览器跑一遍并截图
```

`ui-state-test.js` 专门盯着「弹层打开 / 关闭后 phase 是否回到原处」——
这类 bug 的后果是模拟层被永久卡住，表现就是画面静止、点击无反应。
覆盖：战斗中开合行囊、升级界面开合行囊、商店开合行囊、暂停开合行囊、死亡后拦截。

`sim-test.js` 覆盖：

1. 全部 130 种「模板 × 稀有度」组合能否正常生成
2. 600 次词条 roll 的数值合法性
3. 8 组羁绊是否都凑得出来
4. 6 名角色各跑 12 波（NaN / 击杀数 / 升级次数 / 帧耗时）
5. 10 把武器逐个开火
6. 全羁绊激活 + **行囊容量、满包拒收、饰品入包生效、武器需佩戴**
7. **确定性**：同种子跑两遍结果必须完全一致

## 想改就改

| 想调什么 | 改哪里 |
| --- | --- |
| 行囊格数 | `world.js` → `BAG_SIZE` |
| 波次时长 / 刷怪速度 / 上限 | `world.js` → `WAVE_DURATION`、`updateWave()` |

| 敌人成长曲线 | `enemies.js` → `RG.waveScaling()` |
| 新增武器 | `items.js` 加一条 + `combat.js` 的 `updateWeapon()` 加分支 |
| 新增词条 | `affixes.js` → `RG.AFFIXES` |
| 新增羁绊 | `bonds.js` → `RG.BONDS`（效果走 `mods.xxx`，在 `combat.js` 消费） |
| 新增特性 | `perks.js` → `RG.PERKS`（`apply` 必须幂等） |
| 新增角色 | `characters.js` → `RG.CHARACTERS` |
| 换 UI 配色 | `css/style.css` 顶部的 `:root` 变量 |
| 改某个精灵 | `js/data/pixelart-*.js` 里对应的字符矩阵 |
| 新增精灵 | 同上加一个 `def('名字', 调色板, [16 行字符串])` |
| 改地面质感 | `pixelart-ground.js` 的 `GROUND_PAL` + `pixels.js` 的噪声权重 |

新增装备时 `icon` 字段要指向已有的像素图名，否则会 fallback 成 `rune`。
